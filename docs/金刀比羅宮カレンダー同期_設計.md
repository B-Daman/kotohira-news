## 2. 同期スクリプト `konpira_sync.py`

### 2-1. 起動と引数

- `python -X utf8 scripts/konpira_sync.py [--apply] [--days 90] [--no-git] [--ics PATH]`
- 既定は dry-run（Notion に書かず、結果を標準出力と `konpira-sync-last.*` に出す）。`--ics` は取得せずファイルを使う（オフライン検証用）
- `notion_client` が無い環境では `towncal_register.py` と同じく `notion-event-formatter\.venv` の python で自分を再起動する（登録スキルの実行にも同じ venv を使う）
- 読み取りは `fetch_notion.py`（読み取りトークン）、書き込みは `backfill_calendar.load_write_token()`（資格情報）＋`patch_calendar_values.api()`、新規登録は登録スキル `register_news.py --config config-events-konpira.json`。いずれも既存のものをそのまま使う

### 2-2. 取得と展開

1. 公開 ICS を GET（タイムアウト 30 秒・失敗なら終了コード 2・何も変えない）
2. 取得した本文を `docs/data/konpira-calendar.ics` と比べ、違えば書く（週ごとの差分が git に残る）
3. 展開は 11/5 の試作（scratchpad `compare_ics_notion.py`）を移植: 行の unfold、DTSTART/DTEND（TZID と UTC Z の両方）、RRULE の YEARLY／YEARLY;BYDAY=nXX;BYMONTH=m／MONTHLY;BYMONTHDAY=d、UNTIL、EXDATE、RECURRENCE-ID による差し替え。未対応の RRULE は例外で止める（黙って落とさない）
4. 窓 = 今日〜今日+days（JST）。同じ (日付, 題名) は1つに畳む。MONTHLY の系列は題名ごとに BYMONTHDAY を集め「毎月1・6・10・26日に斎行」の文を作る

### 2-3. 規則ファイル `konpira-sync-rules.json`

```json
{
  "source_url": "https://www.konpira.or.jp/?stageID=hp_calendar&language=JAPANESE",
  "titles": [
    {"ics": "厳魂神社（奥社）例祭", "action": "same", "notion": "厳魂神社大祭", "note": "本人の手入力名"},
    {"ics": "太鼓台清祓式", "action": "new", "note": "同日の御厩神事とは別の行事"}
  ],
  "skip_titles": [],
  "places": [
    {"name": "金刀比羅宮（御本宮）", "page": "1a60b4e5-ff5b-807c-adb7-f25d181a2f7b",
     "match": ["金刀比羅宮 御本宮", "御本宮", "境内", "金刀比羅宮"]}
  ]
}
```

- `titles[].action`: `same`＝同日の `notion` 題名と同じ行事（補完する）／`new`＝同日に別の神社ページがあっても新規登録してよい／`ignore`＝登録しない
- `places[].match` は LOCATION の先頭一致（長いものから試す）。合わなければ relation は付けず、コメントに「場所: …」を残す
- 初期値は 11/5 の突合結果から作る（§5）。要確認が出たら人が1行足す。日付は書かない（毎年効く）

### 2-4. 突合と分類

Notion 側は全ページを読み、窓内の開始日を持つものを日付で索引する。各ページから: id／題名／開始（日付・時刻）／終了／カレンダー／主催／開催場所 relation／ソース／DiscordイベントURL。

1. **同一判定**（ICS 1回ごと、同じ日の未使用ページから）: 規則 `same` の題名一致 → 正規化一致 → 3字以上の内包 → 一致率 0.8 以上。見つかれば `matched`
2. **残り**: 同じ日に未使用の神社ページ（カレンダーか主催に 金刀比羅宮）があり、規則が `new` でなければ `held`（要確認）。無ければ `new`。`skip_titles`／規則 `ignore` は `skipped`
3. `matched` の補完内容を決める（§2-5）。補うものが無ければ `ok`。時刻が入っていて ICS と違えば `conflict`（書かない・報告）

正規化は登録スキルの `normalize_title` と同じ系統（NFKC・空白と括弧類を除く・先頭の「n月n日」を除く）。

### 2-5. 書き込み（`--apply` のときだけ）

**補完（PATCH /v1/pages/{id}・空欄だけ）**

| 列 | 条件 | 値 |
|---|---|---|
| 開催日時（開始） | 日付だけで時刻が無い | `YYYY-MM-DDTHH:MM:00+09:00` |
| 開催日時（終了） | 空で ICS に終了がある | 同上 |
| カレンダー | 金刀比羅宮 が無い | 既存の値＋金刀比羅宮 |
| 主催/運営 | 空 | 金刀比羅宮 |
| 開催場所 | 空で LOCATION が規則に当たる | relation 1件 |
| ソース | 空 | `source_url` |

**新規登録（登録スキル経由）**: 項目 = イベント名／開催日時（開始）／開催日時（終了）／主催/運営=金刀比羅宮／ソース=`source_url`／コメント=「説明文（HTML 除去・1900字まで） / 場所: LOCATION（relation が付かない時だけ） / 毎月…日に斎行（MONTHLY のとき） / 出典: 金刀比羅宮公式カレンダー」。カレンダー=金刀比羅宮・市町村=琴平町は設定の既定値。作成後に 開催場所 の relation を PATCH で付ける。登録スキルが同日類似で `held_title_dup` を返したら `held` に回す（二重の安全網）。

PATCH の間隔は `MIN_INTERVAL`（0.4 秒）。失敗は件ごとに記録し終了コード 1（他の件は続ける）。

### 2-6. 記録と git

- `konpira-sync-last.json`: `{generated, window{from,to}, apply, counts{created,filled,ok,held,conflict,skipped,failed}, rows[]}`。`rows[]` は 1回1件（date, title, status, notion_id, notion_title, fills[], reason）
- `konpira-sync-last.md`: 人が読む一覧。要確認は「同日の既存ページ」を題名の長さに関わらず全部並べ、規則に足す1行の例を添える
- `--apply` かつ `--no-git` でなければ、`docs/data/konpira-*` を `git add`→`commit -m "chore: sync Konpira shrine calendar YYYY-MM-DD"`→`pull --rebase --autostash`→`push`。起動時に未 push のコミットがあれば先に push（`towncal_csv.push_pending` と同じ考え）
- 日曜レポート: `verify_konpira.py` が `konpira-sync-last.json` の `generated` が7日以内なら「⛩ 金刀比羅宮カレンダー: 登録 n・補完 n・要確認 n（kotohira-news docs/data/konpira-sync-last.md）」を今日の `_sns-drafter-weekly_plan.md` に追記（`verify_towncal.py` と同じ作法・常に終了 0）

## 3. フォーラム投稿 `event_forum_poster`（konpie-bot）

### 3-1. 設定（`src/config.py`）

| 変数 | 既定 | 意味 |
|---|---|---|
| `EVENT_FORUM_CHANNEL_ID` | 無し | イベント情報フォーラムのチャンネル ID。**未設定なら cog は無効**（ログ「無効（EVENT_FORUM_CHANNEL_ID 未設定）」） |
| `EVENT_FORUM_DRY_RUN` | false | true なら投稿も書き戻しもせず、内容をログに出す |
| `EVENT_FORUM_LEAD_DAYS` | 14 | 何日先まで投稿するか |
| `EVENT_FORUM_LOOKBACK_DAYS` | 45 | 同題名の再利用で遡る日数 |
| `EVENT_FORUM_MAX_PER_RUN` | 5 | 1回の投稿上限 |
| `EVENT_FORUM_CALENDARS` | 金刀比羅宮 | 対象のカレンダー値（カンマ区切り） |

Notion は `NEWS_NOTION_TOKEN`（書き込み可・イベントDBに接続済み）と `KOTOHIRA_DATABASE_ID`／`KOTOHIRA_DATA_SOURCE_ID` を使う。

### 3-2. 定時処理

- `tasks.loop(time=time(7, 30, tzinfo=Asia/Tokyo))`。`before_loop` で `wait_until_ready`。`DEBUG_FORCE_RUN=true` なら起動直後にも1回
- 1回の処理:
  1. `data_sources.query`: 開始が [今日−LOOKBACK, 今日＋LEAD] かつ カレンダー contains（対象値のいずれか）。100件ずつページング
  2. `targets` = 開始が [今日, 今日＋LEAD] かつ DiscordイベントURL 空（開始順）。`pool` = URL 済み
  3. 各 target（上限 MAX_PER_RUN）:
     - a. `pool` に正規化題名が同じものがあれば その URL を書き戻す（投稿しない）
     - b. フォーラムの既存スレッド（active ＋ archived 100 件）に同名があれば その URL を書き戻す
     - c. それ以外は `ForumChannel.create_thread(name, content)` → 先頭メッセージの `jump_url`（`/channels/{guild}/{thread}/{message}`。既存の手貼り URL と同じ形）を書き戻す
     - 書き戻し = `pages.update(page_id, properties={"DiscordイベントURL": {"url": …}})`。失敗はログ（翌日 b. で拾う）
  4. 件数をログに1行。例外は cog 内で握って翌日に回す（bot 全体を落とさない）

### 3-3. 本文の組み立て（`src/utils/event_forum.py`・純関数）

- 日時: Notion の `start`/`end` を JST に直す。`YYYY-MM-DD` だけなら時刻なし。曜日は 月火水木金土日
  - 同日・時刻あり: `11/10(火)10:00～10:30`／終了なし: `11/10(火)10:00～`／時刻なし: `11/10(火)`／日をまたぐ: `10/10(土)21:00～10/11(日)01:00`
- スレッド名: `{日時} {題名}`（100 字で切る）
- 本文（本人の手順＝formula「投稿文」と同じ並び。「@」は Discord でメンションに見えるので付けない）:

```
## ✅紅葉祭
・11/10(火)10:00～10:30
琴平町：金刀比羅宮（御本宮）
住所：[香川県仲多度郡琴平町892-1（石段785段目）](https://maps.app.goo.gl/…)
参加費：無料            ← 参加費が 0 のときだけ。未入力なら行ごと省く
紅葉の枝の太玉串の…     ← コメント（あれば。600 字で切る）
https://www.konpira.or.jp/?stageID=hp_calendar&language=JAPANESE   ← ソース（無ければ関連リンク）
```

- 場所名は 開催場所 relation 先のページ title（`会場名`）。relation の id → title はメモリ内で cache。住所・地図 URL はイベントページの rollup（`住所`・`GoogleマップURL`）から取る
- 市町村は select。空なら「琴平町」とは書かず行を省く

### 3-4. テスト（`tests/test_event_forum.py`）

- 日時整形 4 形（同日・終了なし・時刻なし・日またぎ）、UTC 入力が JST に直ること、曜日が日本語
- スレッド名の 100 字切り
- 本文: 参加費の有無・コメントの有無・ソース無し→関連リンク
- 再利用: 同題名 URL 済みがあれば投稿しない、正規化（全角半角・空白）で同じとみなす

## 6. 守ること

- 削除しない。既存の値を上書きしない（時刻の食い違いは報告だけ）
- 窓の外（過去）は触らない。2026年の 23 件の時刻補完は 11/5 の一回限りで、再実行はしない
- 同じ日に既存ページがある ICS 行は、題名が短くても必ず要確認として人に見せる
- bot は URL 済みページに触らない。投稿したスレッドを編集・削除しない。ID の値をログや Discord に出さない
- トークンの値を出さない。GitHub Actions には書き込みを置かない（本PCの日曜ランだけ）
- 週1回・1経路。保険の二重実行は置かない
