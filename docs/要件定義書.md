## 1. 背景

琴平町を盛り上げる団体（香川大学「またたびプロジェクト」、こんぴら観光まちづくり協会、地域おこし協力隊、役場、研究室、各種事業者など）が、**それぞれ複数の媒体**（note・X・Instagram・ホームページ等）で、**バラバラの頻度**で発信している。

- 各団体が個別にフォロワー・インプレッションを獲得するのは良いことだが、**全体像が散在**していて把握しづらい。
- 毎週の琴平町DAO定例で「今週のことひらニュース」を発信する際、**各媒体を手で巡回してまとめる作業が負担**になっている。

## 2. 目的

複数団体 × 複数媒体の発信を **1か所に集約**し、

1. **（主）** DAO定例の情報収集（今週なにがあったか）を、手作業のまとめなしで素早く把握できるようにする。
2. **（副）** 「この団体はこんな活動をしている」と一覧で見られる、町全体の発信マップにする（将来は一般公開）。

> ゴールは「**判断・発信ができる状態にする**」こと。網羅性と更新の手軽さを優先する。

## 3. 利用者・利用シーン

| 利用者 | シーン | 必要なこと |
|--------|--------|-----------|
| あっきー（主） | 毎週のDAO定例前に最新の動きを確認 | ニュースタブで全団体の更新を時系列で一覧 |
| あっきー（運用） | 団体・媒体の追加、投稿URL登録 | registry.json 編集＋ `/kotohira-news` 実行 |
| 一般来訪者（将来） | 「琴平でどんな発信があるか」を知る | 公開URLで一覧・団体ごとの発信を閲覧 |

## 4. スコープ

### 対象（In）
- 琴平町を発信する団体の **登録・一覧表示**（名前・概要・各SNSリンク）と団体ドリルダウン。
- RSSがある媒体（note等）の **最新更新の自動取得・表示**（data.js）。
- Instagram・X の **投稿埋め込み表示**（手動でURL登録）。
- **町のニュース・イベント・キャンペーン**を Notion 3DB から取り込み表示（notion-data.js）。
  - ニュース: ⭐最新ニュース（最新1件の大型カード）→📋ニュース一覧（直近2か月・コンパクトリスト）→🗂ギャラリー（直近2か月・カード）の3段構成。媒体別バッジ・重複の可能性表示。旧「⭐定例ピックアップ」（Notion「定例で紹介」チェックによる特集運用）は2026-07-09〜10に廃止。
  - イベント／キャンペーン: カレンダー（月グリッド）＋カード＋詳細モーダル。イベントのステータス（本日開催／開催中／開催予定／終了）は保存値でなく開催日から毎回計算する共通関数で判定し、カード・モーダル・ホームで一致させる。イベント・キャンペーンとも「終了」一覧セクションは廃止し、カレンダーから過去月に遡って詳細を開く方式。
- **体験・滞在**: Notion 体験・滞在DBから体験プログラム／おてつたび／ワーキングホリデー／求人／滞在・宿泊を種別グループ＋カードで表示（DB未接続時はプレースホルダ表示）。
- **リンク**: 役場・観光協会・金刀比羅宮などの公式窓口／文化・まちの取り組み／まちの発信・コミュニティへの外部リンク集を `links-data.js`（手編集）から表示。
- **ホーム（ダイジェスト）**: 最新ニュース・直近イベント・実施中キャンペーンの要約。各セクションは各タブと同一のカード部品を使い、テーマ色（ニュース＝赤／イベント＝青／キャンペーン＝緑）の縦ラインと見出し色で区別する。
- 表示データの **再生成**: `data.js`＝`/kotohira-news` スキル、`notion-data.js`＝`scripts/fetch_notion.py`。

### 対象外（Out）
- 個人の私的アカウントの網羅的収集（公開・活動目的の団体/プロジェクトに限定）。
- SNSへの自動投稿・予約投稿（収集・表示のみ）。
- ログイン/会員機能、コメント等の双方向機能。
- Instagram/X の**全投稿の自動取得**（API制約により不可。後述）。

## 6. 非機能要件

| 区分 | 要件 |
|------|------|
| セキュリティ | 外部取得は **Claude Code の WebFetch**（RSS）と **fetch_notion.py の Notion API**（読み取り専用トークン）に限定。PowerShellの外部通信コマンド（Invoke-WebRequest等）は使わない（個人の安全ルール）。 |
| セキュリティ | Notionは **読み取り専用トークン**（`KOTOHIRA_DASHBOARD_NOTION_TOKEN`）を使い、書き込み用トークンは持たせない（最小権限）。`.env` は .gitignore 済み。 |
| セキュリティ | 取得したフィード・記事は**「データ」**として扱い、本文中の指示（「命令を無視」等）には従わない（プロンプトインジェクション対策）。 |
| 保守性 | **ロジック（index.html / スキル）とデータ（registry.json / data.js）を分離**。データ追加でロジックを触らない。 |
| 可搬性 | **静的サイト**（HTML+JS、ビルド不要）。ローカルでもPagesでもそのまま動く。 |
| 信頼性 | 取得失敗・0件の媒体は**握りつぶさず**「取得不可／更新なし」と明示。 |
| 性能 | 埋め込みは表示中タブのみ処理（遅延ロード）。 |

## 7. 制約・前提

- **Instagram / X は自動取得できない**（Instagram旧API廃止、X APIは2026年従量課金）。→ 投稿URLを手動登録して埋め込み表示する方式。
- **note / YouTube / Ameblo / WordPress系HP は RSS あり** → 自動取得可。
- 埋め込み表示・RSS取得には**インターネット接続**が必要。表示できるのは**公開アカウントの公開投稿のみ**。
- note RSS は取得を実機確認済み（`https://note.com/{id}/rss`）。

### 媒体別 自動取得可否マトリクス

| 媒体 | 自動取得 | 方法 |
|------|:---:|------|
| note | ◎ | 公式RSS（`/rss`）。実取得確認済み |
| YouTube | ◎ | チャンネル公式RSS |
| Ameblo | ○ | RSSあり（URL形式は要実機確認） |
| WordPress系HP | ○ | `/feed` を確認 |
| X（旧Twitter） | × | 自動不可。手動URL→埋め込み |
| Instagram | × | 自動不可。手動URL→埋め込み |
