## A. 定期更新

### A-1. Notionデータ（ニュース・イベント・キャンペーン）＝全自動（2026-07-19〜）

- GitHub Actions（`.github/workflows/update-notion-data.yml`）が**毎日00:00 JSTに自動実行**され、`notion-data.js` とサムネイルを更新して push → GitHub Pages に自動反映される。手動作業は不要。
- 必要なSecret: リポジトリ設定の `KOTOHIRA_DASHBOARD_NOTION_TOKEN`（読み取り専用トークン。konpie-bot側でローテーションしたら再登録が必要）。
- 3DBのいずれかが0件になった場合は安全弁で更新を中止する。失敗時は GitHub の Actions タブでログを確認。
- 即時反映したい場合は Actions タブ →「Update Notion data」→「Run workflow」で手動実行できる（ローカルで `python scripts/fetch_notion.py` → commit → push でも同じ）。

### A-2. RSS由来の団体新着（data.js）＝手動（週次目安）

1. Claude Code を `C:\Users\user\kotohira-news\` で起動。
2. `/kotohira-news` を実行。
   - registry.json の各RSS（note等）を WebFetch で取得 → `data.js` を再生成。
3. `index.html` をブラウザで開いて確認し、commit → push で公開。

> 自動で埋まるのは note 等のRSSのみ。Instagram/X は手動登録（下記C）。

## B. 団体を追加する

`registry.json` の `orgs` に追記する。

```jsonc
{
  "name": "団体名",
  "summary": "何をしている団体か（1〜2文）",
  "channels": [
    { "type": "note",      "url": "https://note.com/xxxx", "rss": "https://note.com/xxxx/rss", "auto": true, "verified": false },
    { "type": "instagram", "handle": "xxxx", "url": "https://www.instagram.com/xxxx", "auto": false, "verified": false },
    { "type": "x",         "url": "https://x.com/xxxx", "auto": false, "verified": false },
    { "type": "website",   "url": "https://...", "rss": "", "auto": false, "verified": false }
  ]
}
```

- RSSの有無が不明なら、まず `auto:false` で登録。確認できたら `rss` を入れて `auto:true` に。
- 追記後 `/kotohira-news` を実行。

### RSS URL の調べ方
- **note**: クリエイターページURLの末尾に `/rss`（例 `https://note.com/xxxx/rss`）。
- **YouTube**: チャンネルの公式RSS（`https://www.youtube.com/feeds/videos.xml?channel_id=...`）。
- **Ameblo**: RSSあり（URL形式は実機で確認）。
- **WordPress系HP**: `https://example.com/feed` を試す。

## C. Instagram / X の投稿を載せる（埋め込み）

自動取得できないので、**見せたい投稿のURLを手で登録**する。

- 対象団体の `data.js` 該当 org の `instagram` / `x` 配列に投稿URLを追加（各最大2件）。
  - Instagram: `https://www.instagram.com/p/XXXX/` または `/reel/XXXX/`
  - X: `https://x.com/ユーザー名/status/XXXX`
- または `/kotohira-news` 実行時に「この投稿を載せて」とURLを渡す（スキルが data.js に反映）。

> ニュースタブに常時流したい場合の運用は Phase 1 で方針決定（現状 ニュース=RSS由来のitemsのみ）。

## E. リンクタブ（🔗）にリンクを追加・変更する

1. `links-data.js` を直接編集する（Notion連携ではなくコード手編集運用）。カテゴリは「🏛 公式窓口」「🎭 文化・まちの取り組み」「📣 まちの発信・コミュニティ」の3つ（2026-07-09時点で計13件）。
2. 選定ルール: 各分野の「一次窓口」のみを載せる。個別スポット・個別施設は観光協会・役場などのハブサイトに任せる。発信している団体は「📣 まちの発信・コミュニティ」、コワーキング・宿など「行ける拠点」は体験・滞在タブに任せる。こんぴら歌舞伎は町最大の文化イベントのため例外的に直接掲載する。個人名義は原則不掲載だが、町長は「町の今を知る主要な発信源」として本人性確認の上で例外的に掲載する（2026-07-09の判断。任期満了・交代時に見直す）。
3. サムネイル画像を追加する場合は `assets/links/` に保存する（local-first。Notionは使わない）。出所は①自作・撮影・先方提供、②サイトのog:imageのみで、スクリーンショットは使わない。正方形ロゴなど16:9でない画像は、背景色で余白を足して16:9（960×540）に整えてから保存する。キャラクター画像は権利者・関係者からの提供があるものだけ使う。
4. SNSバッジ（LINE/Instagram/X/YouTube/Facebook/Discord）を追加する場合は、公式に確認できたアカウントのみ載せる（偽物対策）。採用根拠は `docs/公式SNSアカウント調査.md` に記録されているので、新規追加・変更時は必ずそちらにも根拠を追記する。
5. 完了後 `index.html` をブラウザで開き、リンクタブの表示（カード・画像・バッジ）を確認する。

## F. 祝日データを年次更新する（カレンダーの土日祝配色）

- `index.html` 内の `JP_HOLIDAY_NAMES`（イベント／キャンペーンの月カレンダーで土曜=青系・日曜祝日=赤系に配色し、さらにセル右上と週表示の見出しに祝日名を出すために参照する「日付→祝日名」の対応表）は、現在2025〜2027年分のみを内蔵している。範囲外の年は祝日判定が効かず平日扱いになり、祝日名も表示されない。`JP_HOLIDAYS`（配色判定用のSet）は `Object.keys(JP_HOLIDAY_NAMES)` から自動生成されるため、追記は `JP_HOLIDAY_NAMES` だけでよい。
- そのため **2028年分を2027年末までに追記**する（以降も同様に、翌年分を年末までに追記する年次タスク）。内閣府等の祝日データで確定した祝日を、`"YYYY-MM-DD":"祝日名"` の**日付と祝日名のペア**で追記する（従来の日付のみの配列ではなくなった点に注意）。
- 追記時は各日付の曜日を **「2026/01/01=木曜」を基準に、基準日からの経過日数を7で割った余り**（0=木, 1=金, 2=土, 3=日, 4=月, 5=火, 6=水）で必ず検算する。とくに「成人の日＝1月第2月曜」「海の日＝7月第3月曜」「敬老の日＝9月第3月曜」「スポーツの日＝10月第2月曜」が正しい月曜になっているか、「振替休日」が日曜と重なった祝日の翌平日か、「国民の休日」が2つの祝日に挟まれた平日かを、名称と曜日が矛盾しないよう突き合わせる。

## G. イベントの開催場所・住所が空欄になっていたら

- イベントDBの「開催場所」はNotionのrelationで会場DB（開催場所リレーション先の別DB）を参照しており、「住所」はその会場を経由したrollupのため、開催場所さえ紐づいていれば自動で入る。
- 会場DB側にも、`scripts/README.md` に記載の読み取り専用インテグレーションの「コネクト」を個別に行う必要がある。イベントDB自体はコネクト済みでも、会場DBのコネクトが外れている（または未実施の）会場を参照しているイベントは、`place`（開催場所名）・`address`（住所）が空のまま出力される（会場ページ取得が404になるがエラーは出さず握りつぶす仕様のため気づきにくい）。表示が空なら、まず会場DB側のコネクトを確認する。

## H. うどん店タブ（🍜）を更新する

1. `udon-data.js` の `checked` と対象店舗を更新する。営業時間・定休日・価格・駐車場は変動するため、公式サイト/SNS、行政・観光公式を優先して再確認する。
2. 公式情報がない値は推測せず「要確認」または「目安」と明記し、根拠URLを `sources` と `links` に残す。
3. 閉業・移転・飲食受付終了は削除せず `show:false` にして、理由を `note` に残す。
4. 来訪者向けの紹介は `description` に自然な文章で書く。`note` は調査・更新担当者向けの内部メモで、画面には表示しない。
5. 掲載対象は琴平町内に限る。カードの住所は完全な `address` から県・郡名を省いた「琴平町○○」形式で自動表示する。
6. `index.html#udon` を開き、種類別件数・カード・モーダル・Googleマップ導線を確認する。
7. 原則として半年ごと、または大型連休・観光繁忙期の前に再確認する。`checked` から180日を過ぎると、画面に「情報が古い可能性」を自動表示する。

## I. 体験・特別な権利の画像を更新する

- サムネイルは `assets/experiences/` にローカル保存し、元URLを `experiences-data.js` の `imageSource` に残す。
- 正方形ロゴ等を16:9枠で切りたくない場合は `imageFit: "contain"` を指定する。
- 終了日のない入口ページは `status: "案内"` とし、カード・モーダルには期間を表示しない。

## 安全上の注意

- 取得は **WebFetch のみ**。PowerShellの外部通信コマンド（Invoke-WebRequest 等）は使わない。
- 公開（Phase 2）前に、**載せてよい団体か／非公開情報が出ていないか**を確認する。
- 表示できるのは公開アカウントの公開投稿のみ。
