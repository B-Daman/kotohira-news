## 1. 起きたこと（事実）

- 「第3回こんぴら観光まちづくり検定」（9/3 登録・kankou のイベントページ）に対し、10/5 に「第３回こんぴら観光まちづくり検定試験」（kankou のお知らせページ）が bot「琴平町DB」経由で登録された。bot の重複判定は**ソースURLの完全一致だけ**で、URL が違えば素通りする（画像だけの投稿は URL が空で判定自体が働かない）
- 2026-11-05 の金刀比羅宮60件登録でも、本人が1〜2月に手で入れた「歳旦祭」「斎籠神事 朝祭」「厳魂神社大祭」「初十日祭」「紀元祭（きねんさい）」に対し「歳旦祭・拝賀式」「斎籠神事」「厳魂神社例祭」「初十日祭(初こんぴら)」「紀元祭」を作った。登録スキルの類似判定（NFKC 正規化・内包は短い方が8字以上のときだけ0.9・それ以外は SequenceMatcher≥0.85）は、**題名が短いと一致率が下がって通る**。さらに判定が「日付を見ない」ため、別日の定例行事（月次祭・DAO定例）が毎回「保留」になる逆の問題もある
- 「2月1日・月次祭（…）」が同一題名で2件（1/5 と 2/9 に登録）

## 2. 共通の判定規則（両経路と監査で同じ）

「**同日類似**」＝ 次の両方を満たす既存ページがある

1. 開始日（日付部分）が同じ。複数日の件は期間が重なる
2. 題名を正規化（NFKC・小文字・空白と括弧と記号を除去）して、(a) 一致率 ≥ 0.80、または (b) 一方が他方を内包し短い方が3字以上

該当したら**作らずに止めて人に見せる**。別日の類似（定例行事の繰り返し）は止めない（注記だけ）。

既知の「同日で別の回」のパターン（午前／午後、第一部／第二部、朝祭／夕祭、1日目／2日目、昼／夜）は、正規化の前に**その語を取り除いた上で完全一致したときだけ**別の回とみなして止めない。それ以外は人が判断する。

## 3. konpie-bot（登録チャンネル）

- `notion_register.py` に `find_similar_events(start_iso, title) -> list[{title, url, score, start}]` を足す。開始日の当日〜翌日の範囲を data_sources.query（`開催日時（開始）` の on_or_after／before）で取り、2章の規則で絞る。判定は純関数 `is_same_day_similar(title_a, title_b)` に分け、単体テストできるようにする。クライアントは NotionRegister の書き込みトークン側（`_exists` が同じDBを読めている）
- `register_watcher.py` の `_do`: kind=="event" のとき register の直前に判定。候補があれば登録せず、メッセージに「⏸️ 同じ日に似た行事があります」＋候補（題名・日付・Notion リンク、最大3件）を出し、**「それでも登録」「やめる」の2ボタン**（既存の RegisterView と同じ権限チェック・timeout 900）を付ける。「それでも登録」で通常の register を呼ぶ。「やめる」は「⏭️ 登録しませんでした（候補: …）」を残す
- campaign・news は従来どおり（対象外）
- 判定で例外が出ても登録を止めない（ログに warning。既存の `_exists` と同じ方針）
- テスト: `tests/test_notion_register.py` に `is_same_day_similar` の表（検定／歳旦祭／斎籠神事／厳魂神社／初十日祭／紀元祭＝疑い、午前・午後／第一部・第二部／朝祭・夕祭＝別の回、別日の月次祭＝対象外）。`find_similar_events` は既存のフェイク AsyncNotionClient で query の呼び方を確認。pytest の実行は AGENTS.md の定め（.env の隔離が確認できたときだけ）に従い、できなければ関数単体の実行で確認する

## 4. 登録スキル（`register_news.py`）

- `find_title_dup` を「同日類似」に置き換える: 既存ページの `start` を持ち、2章の規則で判定。別日の類似は `warning: similar_on_other_date` として結果に残すだけで保留しない
- 一致率の閾値を 0.85→0.80、内包の条件を「短い方が3字以上」に

- dry-run の出力に、候補の題名・日付・既存ページURL・一致率を出す（今と同じ形）

## 5. 日次の重複監査（kotohira-news）

- `scripts/audit_duplicates.py`（新規）: 読み取りトークンでイベントDB全件を取り、2章の規則で同日類似の組を列挙。出力は `docs/data/duplicate-candidates.json`（組ごとに2ページの id・題名・日付・作成日・ソース・一致率）と、人が読む `docs/data/duplicate-candidates.md`（表）。`docs/data/duplicate-allowlist.json` にある組（page_id の対）は除く（「これは別の行事」と本人が決めたもの。手で追記）
