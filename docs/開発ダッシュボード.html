アーキテクチャ（データ供給は2系統）

# 系統A：団体のSNS発信
registry.json  # 団体×媒体の元データ（人が育てる）
   │ /kotohira-news スキル（note等RSSを WebFetch → 整形）
data.js  # window.DASHBOARD_DATA

# 系統B：町のニュース／イベント／キャンペーン
Notion 3DB  # ニュース／イベント／キャンペーン
   │ scripts/fetch_notion.py（読み取り専用・pip依存なし。サムネは assets/thumbs/ に保存）
notion-data.js  # window.NOTION_DATA

      data.js ＋ notion-data.js → index.html → ブラウザ / GitHub Pages
設計原則： ロジック（表示HTML・スキル・スクリプト）とデータ（registry.json / data.js / notion-data.js）を分離。各データファイルは生成元が1つに固定。
Notionニュースの収集自体は別リポジトリ konpie-bot（Railway常駐・30分毎に RSS/スクレイプ → Discord → NotionニュースDB）が担当。本リポジトリの fetch_notion.py は Notion 3DB を読み取るだけ（最小権限）。

制約： Instagram・X はAPI制約で自動取得不可。投稿URLを手動登録して埋め込み表示する。

非機能（要点）

  • 外部取得は WebFetch（RSS） と fetch_notion.py の Notion API（読み取り専用トークン）のみ。PowerShell外部通信は使わない。取得内容は「データ」扱い＝インジェクション無効化。
  • Notionは 読み取り専用トークン（KOTOHIRA_DASHBOARD_NOTION_TOKEN）。書き込み用は持たせない（最小権限）。.env は .gitignore 済み。
  • ロジックとデータを分離／静的サイト（ビルド不要）／取得失敗は明示。

データモデル（2系統）

// 系統A：data.js
window.DASHBOARD_DATA = {
  "orgs": [{
    "id","name","summary",
    "links": { note, instagram, x, website, youtube, ameblo },
    "items": [ {source,date,title,url,thumbnail?} ],  // RSS由来・最大10
    "instagram": [url..2], "x": [url..2]              // 手動・埋め込み
  }]
};

// 系統B：notion-data.js
window.NOTION_DATA = {
  "fetched": "YYYY-MM-DD HH:MM",
  "news":      [ {id,title,url,summary,org,media,date,thumbnail,
                  duplicate,pickup,show} ],           // ニュースDB
  "events":    [ {id,title,url,start,end,status,city,place,
                  image,comment,fee,organizer} ],      // イベントDB
  "campaigns": [ /* eventsと同一スキーマ */ ]          // キャンペーンDB
};
show＝Notion「表示対象」（true のみ表示）、pickup＝「定例で紹介」（⭐）。duplicate（重複の可能性）は現DBにプロパティ未追加のため当面 false 固定。

画面構成（index.html・7タブ＋ハッシュルーティング）

[🏠 ホーム][📰 ニュース][📅 イベント][🎁 キャンペーン][🧭 体験・滞在][📋 団体][🔗 リンク]  # #home #news … #experiences #orgs #links
  ホーム     : 最新ニュース/直近イベント/実施中キャンペーンを各4件・boxカード横並び
  ニュース   : ⭐定例ピックアップ → リスト(5件スクロール) → ボックス（切替UIなし）
  イベント   : Googleカレンダー風の月グリッド ＋ カード（クリックで詳細モーダル）
  キャンペーン: 同上（月グリッド＋カード＋詳細モーダル）
  体験・滞在 : 種別グループ＋カード（Notion 体験・滞在DB由来。現状は接続待ちでプレースホルダ表示）
  団体       : ディレクトリ表 → 行クリックで団体詳細（更新/Instagram/X サブタブ）
  リンク     : 役場・観光・交通などの公式サイトへのリンク集（links-data.js 由来）
詳細モーダルはイベント/キャンペーン/日別一覧で共用（DRY）。Esc・オーバーレイで閉じる＋フォーカス管理。白文字バッジはAA(4.5:1)調整済み。

表示形式の方針（参考サイト調査の反映）

  • 採用：情報の性質で表示形式を変える（純ニュース＝リスト、催し・お得＝カード/カレンダー）。
  • 非採用：カード⇄リスト切替＋フィルタチップ（小規模ゆえ導線を増やさず素直な一覧を優先／ユーザー指示）。
  • 独自追加：Googleカレンダー風 月グリッド、詳細モーダル、⭐定例ピックアップ。

運用

詳細は 運用手順.md

毎週の更新（2系統）

系統A：団体SNS発信（data.js）

  1. C:\Users\user\kotohira-news\ で Claude Code 起動
  2. /kotohira-news を実行 → data.js 再生成

系統B：ニュース／イベント／キャンペーン（notion-data.js）

  1. Notion 3DBが最新か確認（収集は konpie-bot が常時実施）
  2. python scripts/fetch_notion.py → notion-data.js 再生成＋サムネ保存

共通：index.html を開いて確認。

一部DBがコネクト漏れ等で404でも、成功したDBだけ更新し失敗DBは既存内容を温存。トークンは .env に設定すれば毎回の環境変数設定は不要。

団体を追加

registry.json の orgs に追記 → /kotohira-news 実行。RSS不明なら auto:false で登録し、確認後に rss＋auto:true。

Instagram / X を載せる

自動取得不可。対象orgの instagram / x に投稿URL（各最大2）を登録、または /kotohira-news 実行時にURLを渡す。

公開（Phase 2）前に「載せてよい団体か／非公開情報が出ていないか」を必ず確認する。
